# Technical debt register

Known shortcuts and gaps, with what each costs and when it must be paid. A living
file: add an entry when a shortcut is taken, delete it when it is paid. Design
context is in `ARCHITECTURE.md`.

**Last reviewed:** 2026-11-08 (stale persistence, CLI, CI and font entries corrected; engine entries not re-audited).  **Size:** S under a session, M a few, L a milestone's worth.

### Hygiene

| ID | Debt | Impact | Pay by | Size |
|---|---|---|---|---|

| TD-18 | **Resolved (U2).** The fake "12 pt" font-size slot and the ribbon's slot mechanism were removed rather than shipped as a control that does nothing. | | | |
| TD-22 | **Done (M2.1).** `tests/parser_golden.rs` records the tree for 75 inputs in `tests/golden/parser.golden`; accept a deliberate change with `UPDATE_GOLDEN=1` and read the diff. | | | |
| TD-29 | M2.1 language decisions to revisit: comparisons give 1 or 0 (no boolean type); equality is exact (no `TOL`); all comparison operators share one precedence level so `1 < 2 == 3` chains left to right; `ORIGIN` is an ordinary variable that indexing reads (default 0, as in Mathcad); `x_i` subscript entry is not parsed (indexing is `x[i]`, typeset as a subscript); `if` evaluates only the chosen branch but counts both for dependencies, so a cycle through an unused branch is still a cycle. ; ranges are lists (`Value::Series`) combined element by element while matrices keep linear-algebra rules, so `k ^ 2` squares each element and `M ^ 2` is the matrix product (whole-number powers only, `M ^ -1` is the inverse); `a, b..c` takes a step from the first two values and is only allowed where a comma cannot separate arguments, so `f(0, 2..10)` is two arguments; `stdev` is the population form (Mathcad) and `stdev_sample` divides by n - 1; a list or matrix cannot be a matrix cell or a range end. | Behaviour that is easy to change now and costly once worksheets exist. | Before Milestone 3 saves real files | S |
| TD-30 | M2.3 function decisions to revisit: **recursion is now allowed (Phase 6, reversing the first decision here)**: a cycle made only of function definitions is fine, while a cycle through a variable is still circular; calls may nest 64 deep (`MAX_CALL_DEPTH`; the evaluation stack is 64 MB, `worker::EVAL_STACK`, and a test checks the deepest recursion of the deepest function bodies fits in half of it) and each call costs a step of the budget; a function body reads variables from the worksheet, not from where it is called, and only its parameters are local; functions and variables are separate namespaces, and a function cannot take a built-in's name; an error inside a body is reported at the call as `in function 'f': ...` without a path into the body; `5 m` is always a quantity in metres even when `m` is a parameter or variable; default arguments exist (Phase 6) but no functions that return several values. | Recursion and local variables are the usual next requests from engineers. | When a worksheet needs them | M |
| TD-31 | M2.4 plot decisions to revisit: plots are painted with the canvas painter (like every region, so they scale with zoom and a drag moves the region), not with `egui_plot`, which needs its own `Ui` and would not follow the canvas zoom; the interactive plot view (hover, pan, zoom, log axes) is a separate window using the same painter, not `egui_plot`; a plot has up to two y axes (left and right), and the series on one axis must share a dimension; axis bounds are automatic unless a limit is given (Phase 3.1); series are expressions that evaluate to a list or vector (no `f(x)` function-plotting syntax, no parametric or bar plots); plot data is evaluated after all math regions, so a plot can read anything and nothing can read a plot; the plot editor lives in the Plot window, not on the canvas; line colours are a cycle of eight, or one chosen per series; the colour is saved as a palette index, so it follows the theme's palette. | An interactive plot is a likely request once real data is plotted. | Milestone 3 or when asked | M |
| TD-24 | **Resolved** (rich text). Inter Italic and Bold Italic are bundled, so italic is a real face. Note they come from `@expo-google-fonts/inter` 0.4.0 while the upright faces are from 0.2.3; slightly different Inter releases. Lucide icons are private-use codepoints and rely on font order. | | | |
| TD-32 | Phase 2.1 calculus decisions to revisit: the forms are function-call syntax (`integrate(f, x, a, b)`), not typeset notation; integrals, derivatives and limits are numerical with stated tolerances and refuse when they cannot reach them (no symbolic result, no improper integrals, first derivative only, two-sided limits only); `sum_over`/`product_over` refuse an empty range; the two bounds of an integral must have the same dimension, so `0` and `3 m` do not mix; an unevaluated bound variable cannot be a unit name written after a number (`2 m` is parsed as a quantity before the variable is known), so use names like `x`, `t`, `k`; the budget counts evaluations, not time; `root` finds real roots of real functions only and, from a guess, the nearest sign change rather than the nearest root; `polyroots` reads coefficients lowest power first and reports repeated roots only to about 1e-8. `odesolve` is an explicit non-stiff method (a stiff equation is an error, not a slow answer), returns the state at the end or a table (not a function of time), and has no events; `col`/`row` are evaluator forms because they count from `ORIGIN`. The solver forms (`find`, `minerr`, `minimize`, `maximize`) are local methods, so the answer depends on the guess and a guess on the wrong side of a constraint can make `find` fail; there is no MultiStart and no complex or matrix unknowns. | Behaviour to settle before the structured editor gives these forms notation. | With the structured editor | S |
